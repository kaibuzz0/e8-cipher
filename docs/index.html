Current conclusion: the legacy v2 cipher is not a secure encryption protocol. The project is rebuilding from verified E8 mathematics upward instead of treating round-trip tests as proof of security.

Research gates

Gate 0 — Genuine E8 mathematics
Construct and mechanically verify the root system, basis, Weyl operations, and E8^N invariants.
Gate 1 — Legacy failure containment
Turn every known catastrophic v2 flaw into a regression test so it cannot return unnoticed.
Gate 2 — Threat model & construction
Specify security goals and decide where E8 belongs: trapdoor, LWE/Module-LWE geometry, coding layer, or nowhere.
Gate 3 — Reference implementation
Build a candidate protocol with CSPRNG randomness, strict serialization, and deterministic test vectors.
Gate 4 — Adversarial verification
Known-plaintext, cross-key, randomness-reuse, lattice-reduction, fuzzing, and statistical attacks.
Gate 5 — Review readiness
Formal specification, concrete attack estimates, benchmarks, side-channel analysis, and independent review.

What changed first

True E8 roots

The earlier code used eight orthogonal directions while discussing 240 roots. The research module now constructs all 240 roots explicitly.

Testable claims

Root count, uniqueness, norm, lattice membership, basis rank, determinant, and Gram determinant are encoded as tests.

Security ≠ functionality

A successful encrypt/decrypt round trip is treated only as correctness. Security requires an attacker model and adversarial evidence.

Repository map

research/e8_lattice.py contains the verified E8 substrate. tests/ contains mathematical and, later, adversarial tests. RESEARCH_PLAN.md is the pass-to-pass handoff checklist. Legacy e8_core.py remains available as the historical v2 experiment while its failures are converted into regression tests.
